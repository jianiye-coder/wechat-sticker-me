# 上传与审核

## 执行前

1. 用户确实要求上传/投稿；只要准备素材不等于授权上传。明确已有授权后直接操作，不再让用户重复确认。
2. 绑定用户指定浏览器/现有页面。按可用电脑工具文档操作；不要通过后台请求、读取Cookie或伪造浏览器状态绕过UI与授权。
3. 首先检查是否已存在同一专辑草稿/审核中记录，接着编辑，避免反复点击提交造成重复。
4. 页面若需要扫码登录，请用户扫码；不要收集用户密码、验证码或身份证到项目文件。

## 页面驱动上传

按页面顺序而非固定旧按钮名称操作：
- 选择合适的专辑/单品、静态/动态类型；单帧GIF不能冒充动画。
- 记录并核实实际要求，必要时先在本地重新导出，再上传。需要用户选择新方案才提问。
- 主图批量上传后，核对成功数量、顺序、逐图预览与含义词；有失败就只补失败项，不能看到文件对话框关闭就当成功。
- 上传封面、聊天图标、详情横幅等页面实际必需项。费用/赞赏等可选项不自动开通。
- 名称/简介用用户最终认可文本。没有最终稿时可以先完成草稿；不要覆盖用户已在页面输入的文案，除非用户要求修改。
- 核对版权字段含义。真实署名/登记/授权由用户事实支持；不得编造版权编号、擅自填写权属声明。AI生成/辅助字段如实填写。
- 在最终提交前读出本次动作的实际效果：保存草稿、提交审核还是立即发布。只做到用户授权范围；若要求接受法律条款等，按当前工具政策在动作发生时请求确认，不能用笼统「全流程」代替。
- 执行后以明确成功消息、状态或记录编号验证。工具允许时保存并展示上下文截图；隐私信息不必传播。

## 状态记录

项目分开记录：本地素材就绪 / 草稿已保存 / 已提交审核 / 审核中 / 被退回 / 审核通过待上架 / 已上架。只能依据真实页面标记；不知道就记录未知。不要因为上传完成就说审核通过。

审核不是同步可保证的步骤，不杜撰时长。需要持续跟进时，仅在用户明确要求后使用环境支持的自动化；否则保留草稿入口/记录编号，告诉用户带回反馈继续。

退回后：提取具体拒因和受影响图片，在项目记录；只修相关内容并重新核验。版权争议需真实材料，不能用改文件名或乱勾声明规避。重新提交需仍在用户当前授权范围内。

## 阻断和恢复

- 网络或文件格式错误：读取报错，修复后重试对应项；同一错误修复后仍重复两次，停止盲试并保留草稿及报告。
- 登录/实名/账户权限缺失：准备完其他材料，停在真实依赖处，请用户完成必要账户步骤。
- 浏览器或站点安全策略明确禁止：不尝试换浏览器、代理、脚本、API或其他路径达成同一被禁止操作。准确说明原因，交付素材包和字段映射供用户手动上传。
- 投稿页不可访问：不能宣称文件已直接可投稿；说明哪些参数是保守制作目标、哪些尚待官方页面确认。
- 用户接管或修改：刷新页面状态后接着做，保留用户新增内容。
