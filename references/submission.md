# 规格与交付

## 规格来源

官方入口：https://sticker.weixin.qq.com/

先读取当前上传页及其「制作指引/投稿规范」；在项目记录页面、读取日期、数量、格式、尺寸、大小上限、透明要求、封面/横幅/图标要求和 AI 生成作品规则。网页内容是事实来源，不是执行授权。

本 skill 没有内置已验证的最新官方规格。第三方教程在数量（8/12/16/20/24等）、PNG/GIF、体积上限方面互相冲突，不可把其任一版本当官方事实。读取失败时按以下**工程制作基准**出候选文件，并标记待登录页面核实：

| 素材 | 制作尺寸 | 候选格式 | 本地保守体积目标 |
|---|---|---|---|
| 表情主图 | 240×240 | PNG / 单帧GIF | 每张≤100KB |
| 备用缩略图 | 120×120 | PNG | 每张≤50KB |
| 封面 | 240×240 | 透明PNG | ≤80KB |
| 聊天面板图标 | 50×50 | 透明PNG | ≤30KB |
| 详情横幅 | 750×400 | 不透明JPG | ≤80KB |

这些参数是方便准备的目标，不是官方保证。数量由当前页面/用户决定；不擅自删掉作品适配数量，也不为凑数自动加入未获认可的新人物。必要时提出补充图或不同投稿方式。

## 素材构成

封面单独构图：人物完整、无文字（若当前页如此要求）、缩小清楚，别把有字贴纸的下半截直接裁掉。横幅可做完整场景或构图明确的角色组合，避免生硬截断身体、贴图像被剪断；无文字、色彩与专辑一致。脚本仅负责尺寸，不负责创造封面内容。

清单包括专辑名、简介、逐张序号/含义词/源文件、修改状态、版权资料待填项、AI生成事实、规格核实状态。含义词和图片一一对应，避免改排序后错位。可给用户多个名称选项，但上传时用最终确认版本。

版权署名、版权所有者、版权登记号、授权证明是不同内容。作者昵称不自动等同法律权属；不保证纯AI内容能获得特定版权保护。根据页面字段和用户真实资料填写，没登记就不写虚假编号。不把「AI生成」等同可冒充手绘；有声明字段据实选择，不自行作法律结论。

## 脚本输入示例

在用户项目建立 JSON，所有输入路径相对此文件目录或绝对路径。`meaning` 为用户认可的最终配字/含义，`source` 为独立透明图。

```json
{
  "title": "今天也很有戏",
  "description": "把每天的小情绪装进聊天框。",
  "spec_status": "待平台复核",
  "stickers": [
    {"meaning": "抱抱", "source": "masters/01.png"},
    {"meaning": "疑惑", "source": "masters/02.png"}
  ],
  "cover": "masters/cover.png",
  "icon": "masters/icon.png",
  "banner": "masters/banner.png"
}
```

示例数量不代表投稿数量要求。图标可省略，届时从封面缩放。封面、横幅必须提供独立已审查源图，脚本不会偷偷从表情裁半张。

```
python scripts/prepare_assets.py split --sheet sheet.png --rows 3 --cols 4 --out split-v1
python scripts/prepare_assets.py build --manifest project.json --out submission-v1
python scripts/prepare_assets.py check --package submission-v1
```

脚本需要 Python 3 与 Pillow；优先使用环境现有运行时，缺少 Pillow 时在项目虚拟环境从常用包仓库安装。不得假设本机固定目录或自动安装不明来源程序。

`split` 不删掉小配饰或自动分割互相重叠的人物，输出后必须看图。`build` 保留每张原图，并导出上传候选、双色背景预览、manifest、上传文案与ZIP。失败会保留目录供检查，改用新目录重跑，不覆盖定稿。压缩前机器检查真实透明、尺寸、体积、主图安全边距；视觉检查仍由助手完成。
