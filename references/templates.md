# 用户可选模板

首次回应制作请求时，先完整展示以下全部模板菜单，每项保留画风与语气、常用表情举例，并说明可以混搭。用户已经说明方向时，展示后直接匹配，不强迫再选；同一制作流程后续无需重复展示。模板是组合起点，不是只有这些选择。

| 模板 | 画风与语气 | 常用表情举例 |
|---|---|---|
| 软萌日常 | 圆润Q版，自然大眼和柔和阴影 | 开心、收到、抱抱、谢谢 |
| 情绪小剧场 | 弹性变形身体，粗笔全身动作 | 震惊、偷笑、抓狂、吃瓜 |
| 冷脸吐槽 | 几何长脸、横线眼、克制平涂 | 行吧、就这、无语、不想动 |
| 打工日常 | 黑白写实脸与简笔身体拼贴，疲惫幽默 | 在忙、稍等、改好了、下班 |
| 甜甜陪伴 | 软萌Q版，亲昵 | 想你、贴贴、等你、哄我 |
| 手帐慢生活 | 手绘涂鸦，松弛温暖 | 喝茶、晒太阳、散步去、歇一会 |
| 黏土小情绪 | 圆润立体黏土，夸张可爱 | 得意、救命、累瘫、撒娇 |
| 像素日常 | 复古像素，简短回应 | 开心、等等、加油、溜了 |
| 精神离线 | 低清抓拍反应图，怼脸失真与尴尬微表情 | 你没事吧、脑干缺失、我好快乐、真服了 |
| 毛毡分身 | 手工羊毛纤维、针织衣物、柔软玩偶 | 探头、抱抱、鼓掌、躺平 |

每个模板的16项动作和文案、3张试稿、候选专辑名、简介、封面与横幅方向统一维护在 [templates/catalog.json](../templates/catalog.json)。文字配方搭配 [README示例画廊](../README.md#可选模板)，每种画风已有4张虚构人物的实际生成示例，位于 `assets/examples/`。它们用于选择风格，不是用户本人的定制结果或已过审范本，也不是直接上传素材；正式制作仍需用户角色参考与独立透明单图。

## 选择与混搭

- 始终先展示全部模板（当前10项），可在完整菜单之后结合用途标注推荐项，不以推荐项替代完整菜单。给用户一个容易回答的选择：“选一种，或说‘冷脸画风＋打工文案’。”不要连续问配色、字体、数量等一长串问题。
- 画风和场景可独立搭配。例：黏土＋打工、像素＋吐槽、Q版＋慢生活。混搭后以同一角色锁定画风，不在同一套中随机切换材质。
- 照片里的外貌和服装优先于模板，不默认作者姓名、性别、发型、肤色。亲昵模板仅在用户选择或关系用途明确时采用，不凭照片猜关系。
- 模板文案可自由替换，候选名称未查重；表情数量依用户意图和当前投稿页调整。不要未经认可补图凑数或自动删除用户指定保留图。
- 试稿词不必出现在最终选题中：优先使用所选模板的trial建议（精神离线为你没事吧、我好快乐、真服了），或用开心、生气、疑惑测试角色后，保留模板自身选题。试稿阶段未获认可时不批量生成。

## 工具用法

```
python scripts/choose_template.py
python scripts/choose_template.py drama-club --out work/brief.json
python scripts/choose_template.py office-life --style clay --title "今天也要下班" --out work/brief-clay.json
```

`choose_template.py` 只产生创意草案，不生成图片、不上传、不填写假source路径。下一步结合用户照片补充人物约束，生成试稿和单图；最终创建具有实际源图路径的build清单。已有文件不覆盖，换版本名。模板选择和用户修改记录在项目，不能把用户自定义回写共享模板库。

精神离线允许脸部近景自然裁切与照片背景，这不是误切掉透明贴纸的轮廓。不要把该风格自动改成白边Q版；有背景方图是否可投稿需核实当前平台。附带build工具目前面向透明单图，不能直接声称支持这些不透明照片方图；用户选此风格时保留原始方图，按平台要求另行导出或抠图，不以造假alpha通过检查。
